# 독립 리뷰 계약

## 입력 묶음

부모 agent는 다음을 전달한다. 이미 제공된 지침·파일은 변경되지 않았다면 다시 읽지 않는다.

- 모드: `diff`(변경분), `plan`(계획), `audit`(현재 상태 감사).
- 요청·성공 조건·변경하지 않을 범위와 필요한 계약 원문 위치. 관련 Phase만 지정한다.
- 정확한 대상 파일 목록과 기준 SHA. diff는 staged/unstaged 및 의도한 untracked 파일을 구분한다. ignored 계획도 대상이면 명시한다.
- 검토할 patch/현재 내용의 기준, 사용자 선행 변경과 이번 변경의 구분, 수행한 검증·결과·미실행 이유.
- 재리뷰는 이전 finding과 수정점, 갱신된 내용 식별값을 전달한다.

필수 입력이 없거나 파일을 읽을 수 없으면 필요한 항목을 구체적으로 반환한다. 불완전한 검토를 무지적으로 처리하지 않는다.

## 범위와 판단

- 파일은 수정하지 않는다. diff는 이번 변경이 만든 문제, plan은 계획의 실현 가능성과 계약 공백, audit는 지정 범위의 기존 문제까지 검토한다.
- 구체적 위험을 확인하는 직접 의존은 최소 범위에서 읽는다. 전체 workflow·전체 계획·과거 대화는 필독 대상이 아니다.
- 실제 요청 충족, 오류/경계/회귀, 개인정보·데이터·외부 입력·계약, 검증 공백, 사용자 변경 보존과 불필요한 범위 확장을 확인한다.
- 미측정 상태를 성공으로 간주하는지, 테스트가 실제 실패를 탐지하는지도 확인한다.
- 근거 없는 가능성·취향·미래 확장을 finding으로 만들지 않는다. 하네스의 영구 규칙 추가를 검토할 때만 ../promotion.md를 참조한다.

## 출력

- finding은 심각도 순서로 심각도·파일:줄·위험·발생 조건·최소 수정 방향을 포함한다.
- 재리뷰는 이전 finding 해결과 수정으로 생긴 회귀를 같은 범위에서 확인한다.
- 완전한 검토에서 finding이 없으면 설명 없이 정확히 다음만 출력한다.

No Findings
